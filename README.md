# Typhoon-Data-Base

台風データベース

気象庁の台風情報を中心に、過去から現在までの台風を検索・可視化・統計分析できるWebアプリです。

FastAPI + SQLite + Leaflet をベースに、1つのPythonファイルを中心として動作します。

⸻

主な機能

1. 予報

現在活動中の西太平洋の台風について、複数の数値予報モデル・アンサンブル予報・AI予報を同一の地図上で比較できます。

表示対象は取得できたデータに応じて自動的に変化します。

単独モデル

* 気象庁 GSM
* ECMWF
* GFS
* UKMET
* NAVGEM
* CMC
* JTWC公式
* HWRF
* HAFS
* COAMPS-TC
* その他、UCAR RALのATCF a-deckに掲載されているモデル

アンサンブル

* GEFS
* CMC-EPS
* NAVGEM-EPS
* ECMWF-ENS
* UKMET-ENS
* JMA-GEPS

AI予報

Google DeepMind Weather Labから取得可能なAIアンサンブルも利用します。

* WeatherNext3
* WeatherNext2
* GenCast

AIデータは取得できない場合もあるため、利用可能なデータだけを自動的に表示します。

予報の表示

予報タブでは、

* 台風の予報進路
* 各予報モデルの初期時刻
* 予報時間
* 予報位置
* 風速
* 中心気圧
* 台風の強さ
* アンサンブルメンバー
* モデル間の位置のばらつき
* 強さの予報

を確認できます。

予報時間はスライダーで変更でき、最大240時間までのデータを扱います。

アンサンブル予報では、各メンバーの進路と平均進路を分けて表示します。

⸻

2. 過去の台風

1951年以降の台風を検索・一覧表示できます。

台風ごとに、

* 台風番号
* 国際名
* 発生時刻
* 消滅時刻
* 継続日数
* 最大風速
* 最低中心気圧
* 移動距離
* 進路
* 強風域
* 暴風域

などを確認できます。

台風の進路は地図上に描画され、時間を指定して台風の位置・風速・気圧の変化を確認できます。

検索・絞り込み

以下のような条件で台風を検索できます。

* 年
* 台風番号
* 国際名
* 最大風速
* 最低気圧
* 継続日数
* 移動距離
* 特徴タグ
* 指定地点からの距離
* 強風域に入った台風
* 暴風域に入った台風

一覧は、

* 号数順
* 発生日順
* 最大風速順
* 最低気圧順
* 継続日数順
* 移動距離順
* 強風域の大きさ順

などで並べ替えられます。

⸻

3. 強風域・暴風域

気象庁の台風位置情報に含まれる半径データを利用し、

* 暴風域（25 m/s以上）
* 強風域（15 m/s以上）

を台風の進路に沿って地図上に表示します。

半径データは radii テーブルに保存されます。

方向別に異なる半径が設定されている場合は、長径・短径を利用して領域を作成します。

半径データが存在する時刻だけが対象となるため、データが存在しない過去の時刻について領域を推測して補完することはありません。

⸻

4. 珍しい台風の自動判定

各台風の位置・風速の時系列から特徴量を計算し、特徴的な台風を自動判定します。

現在実装している主な特徴は、

* 復活
* 越境
* ループ
* 急発達

です。

また、台風の点列から総移動距離なども計算します。

これらの判定結果は feat テーブルに保存されます。

判定結果を確認するための診断機能として、

python app.py featdiag

を利用できます。

なお、これらは観測点列から機械的に判定した参考値であり、気象学的な正式分類ではありません。

⸻

データについて

過去の台風

過去の台風のベースデータには、NOAA/NCEIが公開する IBTrACS（International Best Track Archive for Climate Stewardship） の北西太平洋データを利用しています。

取得するデータから、主に気象庁（TOKYO）の観測値を使用します。

利用する主な項目は、

* 台風ID
* 国際名
* 時刻
* 緯度
* 経度
* 台風の強さ
* 最大風速
* 中心気圧
* 暴風域半径
* 強風域半径

です。

補間用の spur-track は除外しています。

⸻

台風番号

台風番号はIBTrACSの番号をそのまま使用するのではなく、コード内で気象庁方式に合わせて再計算します。

具体的には、各台風について初めて「台風」の強さに達した時刻を求め、その時刻の順番に各年1号から採番します。

そのため、表示上は例えば、

2026年台風第26号 Surigae

のような形式になります。

⸻

当年の台風

現在進行中の年については、過去データとは別の情報源を組み合わせています。

気象庁 台風位置表PDF

気象庁の台風位置表PDFを取得して解析します。

位置表から、

* 時刻
* 緯度
* 経度
* 中心気圧
* 最大風速
* 暴風域半径
* 強風域半径

などを取得します。

速報値のPDFにも対応しているため、確定版が公開される前の台風も扱えます。

気象庁 防災情報JSON

発生中の台風については、気象庁の防災情報JSONから実況情報を取得します。

これにより、位置表PDFだけではまだ掲載されていない最新の実況値を補完します。

デジタル台風

国立情報学研究所の「デジタル台風」も利用します。

これは、気象庁の位置表PDFへの掲載状況などによって発生する空白を補完する目的で使用しています。

⸻

データ更新

サーバー起動時にデータベースの状態を確認し、必要に応じてデータを構築・更新します。

当年の速報データは一定間隔で再取得されます。

更新間隔は環境変数で変更できます。

REFRESH_MINUTES=60

デフォルトは60分です。

また、Web画面側でも5分ごとにサーバー側の更新時刻を確認し、気象庁の速報データが更新されていれば一覧・表示中の台風を更新します。

⸻

データベース

SQLiteを使用しています。

データベースファイルは、

typhoon.db

です。

主なテーブルは以下の通りです。

テーブル	内容
typhoons	台風ごとの基本情報
points	台風の位置・風速・中心気圧の時系列
radii	強風域・暴風域の半径
feat	移動距離・特徴タグなどの解析結果
meta	DB構築などのメタ情報

DB構築時は一時ファイルを作成してから本体を置き換える方式を採用しているため、構築途中の失敗によって既存のDBを直接破壊しないようになっています。

⸻

風速について

データベース内部では風速を kt（ノット） で保持しています。

Web APIおよび画面では m/s に変換して表示します。

1 kt = 0.514444 m/s

過去の台風については気象庁の10分間平均風速を基準に表示します。

予報モデルのATCFデータは原則として1分間平均風速であるため、気象庁の10分間平均相当に合わせるため、

1分平均風速 × 0.88

として比較しています。

そのため、予報モデル間の風速比較ではこの換算を前提としています。

⸻

台風の強さ

過去データと予報で共通の基準を使用します。

10分間平均風速	表示
54 m/s以上	猛烈な
44 m/s以上	非常に強い
33 m/s以上	強い
17.2 m/s以上	台風
17.2 m/s未満	熱帯低気圧

⸻

予報モデルの比較方法

予報の進路比較では、各モデルの予報位置を同じ予報時間にそろえます。

例えば、

+24h
+48h
+72h
+96h
+120h

について、各モデルの位置を比較します。

さらに全モデルの平均位置を計算し、それぞれのモデルが平均位置から何km離れているかを計算します。

これを「位置のばらつき」として表示します。

アンサンブル予報では、

* 平均進路
* 各メンバー
* 風速の平均
* 風速の10〜90パーセンタイル
* 中心気圧の平均
* 中心気圧の10〜90パーセンタイル
* 各強度階級以上となるメンバーの割合

などを計算します。

⸻

予報についての注意

このアプリの予報比較機能は、複数の予報データを同じ画面で比較するためのものです。

予報モデルの取得状況は常に変化するため、毎回すべてのモデルが表示されるとは限りません。

また、モデルの予報値を独自に組み合わせて「公式予報」を作っているわけではありません。

防災上の判断には気象庁などの公式情報を確認してください。

⸻

Web API

主なAPIは以下の通りです。

年一覧

GET /api/years

台風DBの対象年や更新情報を取得します。

台風一覧

GET /api/typhoons

検索条件に応じた台風一覧を取得します。

台風進路

GET /api/tracks

複数台風の進路データを取得します。

台風詳細

GET /api/typhoons/{sid}

指定した台風について、基本情報・進路・風速・中心気圧・強風域・暴風域などを取得します。

統計

GET /api/stats

指定条件に該当する台風について統計情報を取得します。

現在の予報対象

GET /api/forecast/storms

現在取得可能な西太平洋の予報対象を取得します。

台風予報

GET /api/forecast/{sid}

指定台風について、複数モデル・アンサンブル・AI予報をまとめて取得します。

予報診断

GET /api/fdiag

予報データの取得状況などを確認するための診断APIです。

起動方法

必要なPythonパッケージ

少なくとも以下のパッケージが必要です。

pip install fastapi uvicorn requests pdfplumber

⸻

通常起動

python app.py

または、

uvicorn app:app --host 0.0.0.0 --port 8000

環境変数 PORT が設定されている場合は、そのポートを使用します。

⸻

DBを再構築する

IBTrACSからデータベースを新規構築する場合：

python app.py build

この処理では、

1. IBTrACSを取得
2. 必要な列だけを読み込み
3. 台風ごとにデータを整理
4. 気象庁方式で台風番号を再計算
5. SQLiteへ保存
6. 強風域・暴風域を保存
7. 移動距離・特徴タグを計算
8. typhoon.db を生成

という処理を行います。

⸻

診断コマンド

通常の診断

python app.py diag

予報データの診断

python app.py fdiag

珍しい台風・特徴量の診断

python app.py featdiag

⸻

ローカルテスト用データ

環境変数 SOURCE_CSV を指定すると、IBTrACSをインターネットから取得せず、指定したCSVを使用できます。

SOURCE_CSV=/path/to/ibtracs.csv python app.py build

これはデータ処理部分のテストや、外部通信を行わないローカル検証に利用できます。

フロントエンド

フロントエンドは外部のHTMLファイルを必要とせず、Pythonファイル内の PAGE 文字列として組み込まれています。

地図表示には Leaflet を使用しています。

地図タイルには Esri World Dark Gray Base を使用しています。

画面は1ページに統合されており、以下の3タブで構成されています。

│    予報    │  過去の台風  │   統計   │
└────────────┴──────────────┴──────────┘

旧URL

は現在の予報タブ

/#fc

へリダイレクトされます。

自動更新の考え方

このアプリでは、データの種類によって更新方法を分けています。

                    台風データベース
                           │
          ┌────────────────┼────────────────┐
          │                │                │
       過去データ         当年実況           予報
          │                │                │
      IBTrACS       気象庁PDF/JSON       UCAR RAL
                                      │
                              ┌───────┴───────┐
                              │               │
                           数値モデル       AIモデル

過去データは安定したベストトラックを基礎とし、当年については速報情報を追加します。

予報データは別系統として取得し、過去の台風DBには混ぜません。

⸻

データの扱いに関する重要事項

* 速報値は後日修正される可能性があります。
* 予報モデルは取得できない場合があります。
* AI予報も常に取得できるとは限りません。
* 珍しい台風の自動判定は独自アルゴリズムによる参考値です。
* 予報モデル間の比較値は、各モデルのデータ仕様を考慮して換算しています。
* このサイトは予報業務を行うためのものではなく、公開されている観測・解析・予報データを比較・可視化するためのデータベースです。
* 防災上の判断には気象庁などの公式情報を利用してください。

目的

このプロジェクトは、台風に関する観測・ベストトラック・現在の実況・予報モデルを別々に眺めるのではなく、同じ地図・同じデータベース上で横断的に比較できる環境を作ることを目的としています。

特に、

* 過去の台風を調べる
* 台風の進路を比較する
* 強風域・暴風域を見る
* 台風の特徴を統計的に調べる
* 現在の複数予報モデルを比較する
* アンサンブル予報のばらつきを見る
* AI予報と従来型モデルを比較する

といった用途を1つのWebアプリにまとめています。
